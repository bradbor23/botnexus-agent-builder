# Gateway extension — `botnexus-agent-builder`

Serves the Agent Builder SPA **from the BotNexus gateway itself**, at
`http://<gateway>/agent-builder`. Because it's same-origin, the read panel calls
`/api/agents` with no CORS configuration.

It's a standard BotNexus endpoint-contributor extension:

- `BotNexus.Extensions.AgentBuilder.csproj` — references `BotNexus.Gateway.Abstractions`;
  bundles `botnexus-extension.json` + `wwwroot/**` into the build output.
- `AgentBuilderEndpointContributor.cs` — `IEndpointContributor` that serves `wwwroot/`
  under `/agent-builder` (SPA fallback to `index.html`, immutable cache for `/assets/`).
- `botnexus-extension.json` — manifest (`extensionTypes: ["endpoint-contributor"]`).
- `wwwroot/` — the prebuilt SPA (generated by `bundle.sh`; git-ignored).

## Build & deploy (on the gateway host)

The extension must live in the gateway repo so it builds against the Abstractions
project and is picked up by the CLI's deploy step.

1. **Stage the SPA** (from this repo, where npm/vite exist):
   ```bash
   ./gateway-extension/BotNexus.Extensions.AgentBuilder/bundle.sh
   ```
2. **Place the folder** in the gateway worktree:
   ```
   <gateway-repo>/src/extensions/BotNexus.Extensions.AgentBuilder/
   ```
   (including the generated `wwwroot/`).
3. **Build + deploy + restart** via the normal dev loop — the CLI scans
   `src/extensions/**`, builds each, and deploys to `~/.botnexus/extensions/`:
   ```bash
   pwsh scripts/start-gateway.ps1
   ```
4. **Verify**: open `http://<gateway>:5005/agent-builder`. The gateway logs should show
   the extension loaded (`botnexus-agent-builder`), and **Load agents** should work
   against the same-origin `/api/agents` with no CORS setup.

No `config.json` change is required: `gateway.extensions` is already enabled and the
manifest ships `enabled: true`.
